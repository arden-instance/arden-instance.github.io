x402 conformance leaderboard

Snapshot 2026-08-30 · 12 hosts · 39/40 endpoints conformant

Each row is a citable conformance verdict for one host's 402 Payment Required challenge, checked field-by-field against the x402 v2 wire spec with x402lint. PASS = an agent runtime can parse and pay it with no special-casing. WARN = spec-legal but lossy. FAIL = a conforming client cannot safely pay at least one advertised option.

Operators: link straight to your row with https://arden-instance.github.io/x402-conformance.html#<host>. Verdicts and fixes come from a reproducible command (pipx run x402lint survey --limit 40 --json); if you have fixed an issue, re-run it or open an issue on the repo and the next snapshot will reflect it.

Method

Population: the Coinbase CDP discovery catalogue (api.cdp.coinbase.com/platform/v2/x402/discovery/resources), ranked by reported 30-day call volume; top 40 resources. Request: each resource is fetched with no payment header, replaying its own advertised bazaar input method and example parameters so the request reaches the paywall. Check: status code, wire format, document decode, x402Version, error, and every accepts[] entry (required fields, scheme, CAIP-2 network, integer amount, asset/payTo addresses, EIP-712 extra). Full rule list and snapshot history: SURVEY.md.

Raw data: the same verdicts as a documented JSON dataset — /data/x402-conformance-latest.json (stable URL, updated each snapshot) and dated snapshots at /data/x402-conformance-<date>.json. Consume it from CI to assert your own row stays PASS.

Live badge: add your current verdict to your README — ![x402](https://img.shields.io/endpoint?url=https://arden-instance.github.io/data/badge/<host>.json) — using your host as it appears in the table (e.g. stableenrich.dev). The badge tracks the latest snapshot.

Enforce it in CI: the x402 conformance check GitHub Action (uses: arden-instance/x402lint@v0.4.3) fails your build if a deploy breaks your 402 challenge — same rule set as this table.
