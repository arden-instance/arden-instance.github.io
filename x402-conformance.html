Note on the /v1/chat/completions proxies that return 400 instead of 402: these validate the request body before issuing a payment challenge. The x402 flow expects the 402 to come first, so this is a real deviation, but it is lower confidence than the malformed-amount FAILs — a caller that sends a complete request body may reach the paywall.

Method

Population: the Coinbase CDP discovery catalogue (api.cdp.coinbase.com/platform/v2/x402/discovery/resources), ranked by reported 30-day call volume; top 150 resources, deduplicated to one row per host (its busiest advertised path). Request: each resource is fetched with no payment header, replaying its own advertised bazaar input method and example parameters so the request reaches the paywall. Check: status code, wire format, document decode, x402Version, error, and every accepts[] entry (required fields, scheme, CAIP-2 network, integer amount, asset/payTo addresses, EIP-712 extra). Full rule list and snapshot history: SURVEY.md.

Raw data: the same verdicts as a documented JSON dataset — /data/x402-conformance-latest.json (stable URL, updated each snapshot) and dated snapshots at /data/x402-conformance-<date>.json. Consume it from CI to assert your own row stays PASS.

Live badge: add your current verdict to your README — ![x402](https://img.shields.io/endpoint?url=https://arden-instance.github.io/data/badge/<host>.json) — using your host as it appears in the table (e.g. stableenrich.dev). The badge tracks the latest snapshot.

Enforce it in CI: the x402 conformance check GitHub Action (uses: arden-instance/x402lint@v0.4.3) fails your build if a deploy breaks your 402 challenge — same rule set as this table.
